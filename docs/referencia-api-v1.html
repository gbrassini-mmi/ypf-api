Referencia de API · v1

ypf-api

Datos de los equipos de bombeo asignados a YPF: listado de equipos, pozos del servicio, último valor de cada tópico, histórico de un tópico y eventos de desarenado. Todas las rutas son de solo lectura, usan JSON y requieren un access token válido.

Versión v1 (prefijo /v1) Formato application/json Fechas ISO 8601, UTC URL base se entrega con las credenciales

Autenticación

La API no emite tokens. El consumidor pide un access token a Amazon Cognito con el flujo OAuth 2.0 client_credentials (máquina a máquina) y lo envía en cada request en el header Authorization: Bearer <access_token>. El client_id y el client_secret se entregan por canal seguro.

1 · Obtener el token
curl -X POST 'https://dcore.auth.us-east-1.amazoncognito.com/oauth2/token' \
  -H 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'grant_type=client_credentials' \
  --data-urlencode 'client_id=<CLIENT_ID>' \
  --data-urlencode 'client_secret=<CLIENT_SECRET>' \
  --data-urlencode 'scope=msuite/read'
Respuesta 200
{
  "access_token": "eyJraWQiOiJ...",
  "token_type": "Bearer",
  "expires_in": 3600
}

Vigencia de 60 minutos

Reusar el mismo token para todos los requests y renovarlo un poco antes de expires_in. No pedir un token por request.

Scope msuite/read obligatorio

Es el único scope que se pide. Un scope mal escrito devuelve 400 invalid_scope en Cognito, y un token sin msuite/read recibe 400 en cualquier ruta de la API.

El secret no viaja a la API

Solo se usa contra el token endpoint. Guardarlo en un gestor de secretos, nunca en código, URLs ni logs.

Qué equipos ve cada token

Cada token pertenece a una credencial asociada a una o más cuentas. En cada request la API resuelve esas cuentas (y sus subcuentas) y solo expone los equipos que tienen un servicio activo hoy en alguna de ellas.

Servicio activo

Un equipo está asignado a una cuenta durante un período. Fuera de ese período, o si el servicio o el equipo fueron dados de baja, deja de aparecer.

Datos actuales: servicio activo hoy

En el detalle y en /live, un equipo que no aparece en GET /v1/equipment devuelve 403, aunque el serial exista.

Datos históricos: período contratado

El histórico y los desarenados no exigen un servicio activo hoy: devuelven solo los tramos del rango pedido cubiertos por un servicio de las cuentas del token. Ver rangos contratados.

Permisos al instante

Los permisos se consultan en cada request, sin caché: un cambio de asignación aplica en la llamada siguiente.

Errores comunes

Aplican a todas las rutas. Cada endpoint lista además sus propios casos.

HTTPCuándoQué hacer
400El token no incluye el scope msuite/read. También parámetros inválidos, según cada endpoint.Pedir el token con scope=msuite/read. Corregir el request; no reintentar igual.
401Token ausente, mal formado, vencido, de otro emisor o que no es un access token.Pedir un token nuevo y reintentar una sola vez.
403La credencial no tiene el permiso DEVICE_READ, o el equipo pedido no está visible para el token.No reintentar. Revisar asignaciones con el equipo de soporte.
503El servicio de autorización (o, en desarenados, el de eventos) no está disponible. La API falla cerrada: nunca responde datos sin validar permisos.Reintentar con backoff exponencial.

Endpoints

El equipo se identifica por su número de serie (serial). Todas las rutas requieren el permiso DEVICE_READ.

GET /v1/equipment ▼

Equipos asignados a YPF con un servicio activo hoy.
Alcance del token

Devuelve solo los equipos con un servicio activo en alguna de las cuentas a las que tiene acceso el token enviado en Authorization. Dos credenciales distintas pueden ver listados distintos.

Comportamiento

  • Un equipo aparece una sola vez, aunque esté activo en varias cuentas del token. Se informan las fechas de su servicio activo más antiguo.
  • endDate es null mientras el servicio no tenga fecha de fin.
  • Si el token no tiene equipos visibles, la respuesta es 200 con una lista vacía.
  • Sin paginación ni filtros por ahora.

Detalle del equipo: fechas de su servicio y pozos activos.
Alcance del token

Responde solo si el equipo está visible para el token (ver visibilidad). Un serial inexistente y uno de otra cuenta responden igual, 403, para no revelar qué equipos existen.

Comportamiento

GET /v1/equipment/{serial}/well/{wellNumber}/topics/{topicKey}/history ▼

Histórico paginado de un tópico de un pozo, del más nuevo al más viejo.
Alcance del token

Devuelve solo los tramos de [from, to] en los que el pozo estaba en un servicio de las cuentas del token. El servicio no necesita estar activo hoy: el histórico de un contrato terminado se puede leer para el período que cubrió. El campo ranges indica qué tramos se leyeron.

Comportamiento

  • Mediciones ordenadas por timeStamp descendente, una por instante.
  • Valores crudos, tal como los reporta el equipo (sin multiplicador ni unidad).
  • total cuenta las mediciones de todos los tramos, no solo de la página.
  • Paginación por número de página. Rangos muy amplios y páginas muy profundas responden más lento.
A definir con YPF

El rango máximo de fechas y los límites de paginación. Hoy limit va de 1 a 1000 y no hay tope de rango.

GET /v1/equipment/{serial}/wells/{wellNumbers}/sanding-events ▼

Eventos de desarenado de uno o más pozos en un período, del más nuevo al más viejo.
Alcance del token

Misma regla que el histórico, aplicada por pozo: cada pozo devuelve solo los eventos de los tramos en que estaba en un servicio de las cuentas del token. Un pozo nunca muestra eventos de fuera de sus propios contratos.

Comportamiento

  • Varios pozos en un solo request: 1,2,3. Se ordenan y se eliminan repetidos.
  • Devuelve un elemento por pozo pedido, en orden ascendente, aunque no tenga eventos (eventCount: 0).
  • Sin paginación: se devuelven todos los eventos de los tramos contratados.
  • drainWeight es el valor crudo del equipo (libras × 10), o null si no se informó.
  • insertType es "MANUAL" para eventos cargados a mano y null para los automáticos.

Parámetros

NombreEnTipoDescripción
serialpathstringObligatorio. No vacío, máximo 50 caracteres.
wellNumberspathstringPozos separados por coma, solo dígitos, sin espacios ni elementos vacíos. Se rechazan 1,,2, 1, y 1, 2.
fromquerydate-timeObligatorio. ISO 8601 estricto, preferentemente en UTC (Z).
toquerydate-timeObligatorio. ISO 8601 estricto, no anterior a from.

Rangos contratados

El histórico y los desarenados reciben un rango [from, to] y lo recortan a los períodos en que el pozo estuvo en un servicio de las cuentas del token. Solo cuentan los servicios que incluyen ese pozo.

Superposición parcial

Si el rango cubre solo una parte de un contrato, se devuelve esa parte.

Huecos entre contratos

Si el rango cruza un período sin contrato, se devuelven los tramos de cada lado. Los tramos que se tocan se unen en uno.

Campo ranges

Lista los tramos efectivamente leídos, con ambos extremos incluidos. Si no hay ninguno, la respuesta es 403.
